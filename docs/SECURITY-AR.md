# في هذا الملف: ما تم إصلاحه، وكيف تُشغّل قاعدة البيانات في 3 خطوات.

## أولًا: الثغرات الثلاث — أُغلقت ✅

| الثغرة | قبل | بعد |
|---|---|---|
| 1. أي شخص يقرأ مفاتيح أي مستخدم | `GET /api/fish/keys?fishUserId=…` يرجّع المفتاح كاملًا | يرجّع المفتاح **مقنّعًا** (`ak_**AB12`)، والنص الكامل يُرجَع فقط لمالكه بعد التحقق من هويته |
| 2. إنشاء مفتاح لأي مستخدم | يقبل أي `fishUserId` من المتصفح | يتحقق من **Firebase ID Token**، ويمنع إنشاء مفتاح لحساب آخر |
| 3. لا حد لعدد المفاتيح | غير محدود | حد أقصى **10 مفاتيح** لكل مستخدم (قابل للتغيير) |

## ثانيًا: حماية المفاتيح في قاعدة البيانات

- يُخزَّن المفتاح **مشفَّرًا** بـ AES-256-GCM، ولا يوجد نص صريح في الجدول.
- يُخزَّن معه **بصمة SHA-256** للبحث السريع فقط (لا يمكن استرجاع المفتاح من البصمة).
- الوصول إلى الجداول عبر **RLS**: المتصفح (anon) لا يرى أي صف، والسيرفر فقط يقرأ بمفتاح `service_role`.

## ثالثًا: تشغيل قاعدة البيانات (3 خطوات)

1. من **Supabase** أنشئ مشروعًا جديدًا (اختر أقرب منطقة: `eu-central-1` أو `me-central-1`).
2. افتح **SQL Editor → New query** والصق محتوى الملف `supabase/schema.sql` ثم **Run**.
3. من **Project Settings → API** انسخ:
   - `Project URL` → ضعه في `SUPABASE_URL`
   - `service_role` (وليس anon) → ضعه في `SUPABASE_SERVICE_ROLE_KEY`

ثم في ملف `.env` على السيرفر:

```env
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_SERVICE_ROLE_KEY=eyJhbGciOi...
# مفتاح تشفير المفاتيح (32 بايت base64) — أنشئه مرة واحدة واحتفظ به
FYSH_ENCRYPTION_KEY=
# اختياري
FYSH_MAX_KEYS_PER_USER=10
FYSH_REQUIRE_AUTH_FOR_KEYS=true
FIREBASE_PROJECT_ID=fysh-7f8ea
```

> إذا تركت `FYSH_ENCRYPTION_KEY` فارغًا، يُنشئ السيرفر مفتاحًا ويحفظه في
> `data/.fysh-store-key` (صلاحيات 600). لا تفقده: بدونه لا يمكن فك تشفير المفاتيح.
> عند تشغيل أكثر من نسخة، ضع نفس القيمة في متغيّر البيئة عند الجميع.

بعد إعادة التشغيل ستجد في السجل: `[STORAGE] loaded N keys from Supabase`.

## رابعًا: قبل فتح التسجيلات للعامة

- [ ] `FYSH_REQUIRE_AUTH_FOR_KEYS=true` (يمنع أي مفتاح بدون تسجيل دخول).
- [ ] تفعيل تسجيل الدخول (Google) في Firebase Console → Authentication.
- [ ] نسخة احتياطية دورية: Supabase → Database → Backups.
- [ ] مراقبة الاستخدام من جدول `fysh_key_usage`.
- [ ] عند تجاوز ~5,000 مستخدم نشط: شغّل نسختين من السيرفر خلف موازن تحميل
      (البيانات صارت في قاعدة بيانات، فلا تعارض).

## خامسًا: كيف يعمل السيرفر الآن

```
المتصفح ──(Firebase ID Token)──▶ /api/fish/keys/create ──▶ تشفير AES-256-GCM ──▶ Supabase
الوكيل  ──(ak_live_…)──────────▶ /api/fish/mcp ──▶ بحث بالبصمة ──▶ فك التشفير ──▶ جلسة Composio
```

المفتاح لا يُرسَل إلى Composio ولا يُسجَّل في السجلات، ويُحدَّث `last_used_at` عند كل استخدام.
